# Portable Web Toolkit v0.6.4

Host setup release, verified by running the setup for real on a macOS 26 guest and a Windows Server 2025 guest.

## Changed

- **Node resolves at run time.** No Node version or URL is stored anywhere: setup reads nodejs.org's latest release of the `.node-version` major (now a bare `26`) and verifies its SHA-256 before installing (tarball on macOS/Linux, `.msi` on Windows).
- **pnpm is a core tool**, installed when missing in user scope (no admin).
- **Enchi replaces pyenv-native** (renamed in 0.8.0). `enchi` is detected first, the legacy `pyenv` second; an old install is upgraded in place. The `pyenv-gui-*` downloads that now return 404 are replaced by the checksum-verified `enchi-gui-*` assets.
- One shared detection library per platform for the wizard and bootstrap.
- The weekly `toolchain-refresh` workflow is now an agent task in the `toolkit-update` skill.
- `CLAUDE.md` added (imports `AGENTS.md`); `AGENTS.md`, the skills and the onboarding stages say pnpm and Enchi.

## Fixed

- macOS: bash 3.2 aborted `bootstrap.sh` (`${var,,}`) and the wizard still printed "SUCCESS".
- Passwordless-sudo accounts were blocked by `sudo -v`.
- Windows: a `$Args` parameter made every `enchi` call drop its arguments; an unset variable broke Node resolution under strict mode.
- The Node doctor read the version inside a path instead of the tool's own version.

Requires WCAGate 2.4.2 or newer (unchanged; `#semver:*` resolves it).
