# Portable Web Toolkit v0.3.8

Fix `init-site-profile` default output + clarify `.env.example` ownership.

## Highlights

- **`init-site-profile create`** writes into the **client project** (`./<siteId>.site-profile.json`) by default — no more accidental toolkit `site-profiles/` client files.
- Agent-ready README/help + `requirements --json`; full optional flag list documented.
- Root `.env.example` is a pointer only; use **`site-starter/.env.example`** for client sites.

## Example

```bash
node ./Web_Toolkit/init_site_profile/bin/init-site-profile.mjs requirements --json
node ./Web_Toolkit/init_site_profile/bin/init-site-profile.mjs create \
  --site-id bakery \
  --project-root . \
  --deploy-target workers \
  --zone bakery.com \
  --prod-hosts bakery.com,www.bakery.com
```
