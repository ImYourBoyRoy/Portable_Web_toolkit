# Portable Web Toolkit v0.6.5

The setup engine release. Host setup is now a tested Rust binary (`toolkit-setup`) instead of two drifting script sets, verified on a
bare Ubuntu, a Mac and a Windows Server guest.

## Added

- **`toolkit-setup`** (`Web_Toolkit/setup_engine/`): `plan`, `install [item…]`, `status`, `events`, `session` for Git, Node, pnpm, Enchi,
  Enchi GUI, Python (workspace venv) and Python Playwright on Windows, macOS and Linux. One OS approval opens a short administrator
  session that serves only three closed operations (`node.install`, `git.install`, `python.build_deps`); a failed item is retried by
  name with no new prompt; a session the run opened is closed when everything succeeded. The engine never reads a password.
- Progress is `.runtime/setup/state.json` plus `events.jsonl`, written by the unprivileged process, for a model or a GUI to follow.
- The launchers download the engine for the toolkit version from this release (SHA-256 verified, version recorded beside it) and use the
  scripts when it is missing, stale or cannot start (`TOOLKIT_SETUP_LEGACY=1` forces the scripts).

## Hardened (independent review, then re-tested on real machines)

- The elevated worker ignores the environment, uses absolute system tool paths, downloads into an exclusive administrator-only folder,
  does not restore archive owners, refuses a Node major below the one it was built for, and writes no files in the user's folder.
- The Windows Node MSI must carry a valid OpenJS Foundation signature in addition to its SHA-256.
- One install run at a time; the state folder is `0700`; `sudo toolkit-setup install` installs only Git and Node.

## Fixed

- The Windows wizard in v0.6.4 could not start (a stray backtick), and Windows PowerShell 5.1 could not parse it (non-ASCII text);
  `.ps1` and `.bat` files are now ASCII, enforced by a test.
- A Windows checksum check could never pass (GitHub serves `.sha256` as bytes).
- Linux minimal machines: Node needs `libatomic`, Python needs a compiler and headers, `enchi versions` exits non-zero when no Python
  exists yet, and pnpm 11+ keeps its binary in `$PNPM_HOME/bin`. All handled; a bare Ubuntu with only `curl` now installs everything.

## Known limits

- The UAC prompt, the macOS dialog and `pkexec` could not be exercised without a desktop; passwordless `sudo`, root and the
  elevated Windows session were. Other processes of the same user are inside the approval window, as with a `sudo` timestamp.
- Binaries are not code-signed, so SmartScreen and Gatekeeper can warn on a downloaded copy.
- Only Ubuntu was run clean; Fedora, Arch and openSUSE package names are unit tested, not run.
